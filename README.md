# Система анализа качества связи

Учебный проект Семёнова А.В., группа ИИ-26. Предметная область — техническая
поддержка и анализ качества услуг Брестского филиала РУП «Белтелеком».
Программа не является официальным продуктом оператора. Данные демонстрационные,
подключение к производственной сети и обработка сведений об абонентах отсутствуют.

## Запуск в PyCharm

Проверено на Windows и Python 3.12 (64 бит).

1. Распакуйте `telecom_analyzer.zip` в папку с правом записи.
2. В PyCharm выберите **Open** и откройте папку `telecom_analyzer` с `main.py`.
3. Создайте для проекта виртуальное окружение **Virtualenv** с Python 3.12.
4. В терминале PyCharm выполните `python -m pip install -r requirements.txt`.
5. Откройте `main.py` и выберите **Run 'main'**.
6. Нажмите **Демонстрация**. После обработки доступны таблица, график, история
   и вкладка **Оценка качества**.

Интернет нужен для первоначальной установки библиотек. Веса модели скачивать
не нужно: Isolation Forest обучается локально. После установки зависимостей
приложение работает без Интернета. PyCharm отдельно не автоматизировался при
проверке; протестированы Python-код и интерфейс Qt в той же ОС.

Командный запуск: `python main.py`. Если библиотека не найдена, проверьте, что
команда установки и Run используют один интерпретатор. В путях допускаются
пробелы и кириллица. Файл `telecom.db` создаётся рядом с `main.py`, независимо
от текущего рабочего каталога. Если база недоступна, перенесите распакованный
проект в доступную для записи папку. Не запускайте программу прямо из ZIP.

## Порядок работы

- **Демонстрация**: эталон из 1000 нормальных измерений (seed=42), обучение и
  анализ 600 независимых измерений (seed=77), автоматическое сохранение запуска.
- **Эталон CSV**: обучить новую модель на не менее чем 100 измерениях нормальной
  работы. Значение `label=1` и постоянные признаки в эталоне запрещены.
  Неразмеченный эталон допустим, но его нормальный режим должен подтвердить пользователь.
- **Импорт CSV**: загрузить измерения для анализа. Он не обучает модель.
- **Анализировать**: применить текущую модель и сохранить новый запуск.
- Фильтры узла и аномалий изменяют таблицу, график и сводку.
- Выберите строку, чтобы увидеть диагностическое пояснение.
- **Экспорт CSV**: сохранить только строки текущего фильтра с результатами.
- **История**: дважды щёлкните по запуску, чтобы восстановить сохранённые
  измерения и решения. Модель не сохраняется; после перезапуска для нового анализа
  загрузите эталон. Просмотр и экспорт сохранённого результата не требуют обучения.

Во время обучения/анализа команды изменения данных блокируются. Для закрытия
окна дождитесь окончания вычисления. Каждый анализ — отдельный запуск; история
не удаляется и не заменяется при повторном анализе того же файла.

## Формат CSV

Кодировка UTF-8 (BOM допустим), разделитель `;`. Первая строка — названия столбцов:

```text
timestamp;node;latency_ms;jitter_ms;loss_pct;utilization_pct;label
2026-06-15 08:00:00;BR-DEMO-01;18.1;3.0;0.12;45.0;0
```

| Поле | Содержание |
|---|---|
| timestamp | Местные дата и время ISO без часового пояса |
| node | Условный идентификатор до 40 символов: буквы, цифры, `_`, `-`, `.`; первый символ — буква/цифра |
| latency_ms | Задержка, от 0 до 1 000 000 мс |
| jitter_ms | Джиттер, от 0 до 1 000 000 мс |
| loss_pct | Потери пакетов, от 0 до 100 % |
| utilization_pct | Загрузка канала, от 0 до 100 % |
| label | Необязательная разметка: 0 — норма, 1 — аномалия, пусто — неизвестно |

Поддерживаются десятичные точка и запятая. Пары времени и узла не должны
повторяться. NaN, бесконечности, отрицательные показатели, пустые обязательные
поля, неверные даты и файлы без записей отклоняются. Ограничение: 10 000 строк
и 10 МБ. При ошибке не загружается весь файл, предыдущие данные остаются открытыми.
Дополнительные столбцы игнорируются. Для экспорта добавляются `anomaly`, `score`
и `symptom`; экспорт можно снова импортировать как набор измерений.

Готовые файлы находятся в `data/baseline.csv` и `data/measurements.csv`.
Не включайте персональные данные и внутренние адреса оборудования.

## Алгоритм и результат

Isolation Forest — алгоритм машинного обучения, не нейросеть. Он реально обучается
на четырёх признаках и вычисляет `decision_function` для новых наблюдений.
Используются 200 деревьев, `contamination=0.02`, `random_state=42`, `n_jobs=1`.
Время, узел и label не входят в признаки. Отрицательная оценка означает аномалию;
оценка не является вероятностью аварии. Contamination влияет на порог по эталону,
но не задаёт фиксированное число аномалий на новых данных.

Пороговые пояснения (50 мс задержки, 10 мс джиттера, 1 % потерь, 85 % загрузки)
служат только объяснению симптомов. Они не определяют решение ML и не являются
официальными нормативами Белтелекома. Причина неисправности автоматически не определяется.

Контрольный результат: TP=52, FP=6, FN=8, TN=534; Precision=0.8966,
Recall=0.8667, F1=0.8814. Это измерения, а не количество аварий. Метрики вычисляются
по всем строкам с label независимо от фильтра. При частичной разметке оценивается
только размеченная часть. Отсутствие разметки не препятствует анализу.

Наборы обучения и контроля генерируются разными seed. Данные искусственные,
модель не оценена на реальной сети. Общая модель рассчитана на сходные профили
трёх условных узлов; для неоднородного оборудования нужны отдельные эталоны.
Модель не учитывает временные последовательности, сезонность и корреляцию инцидентов.

## Структура программы

`main.py` содержит модель Measurement, алгоритм Detector, хранилище Store,
рабочий поток Worker, график Plot и окно Window. Интерфейс обновляется в главном
потоке, обучение и анализ выполняются в QThread. SQLite-соединения явно закрываются.
Таблицы `runs` и `measurements` связаны идентификатором запуска. Сохранение
выполняется транзакционно. Сохранённый `score` округлён до шести знаков;
решение принято до округления и хранится отдельно в `anomaly`.

## Проверка

В терминале проекта: `python -m unittest -v`.

Семь тестов проверяют качество на независимом наборе, отсутствие утечки label,
защиту обучения, CSV и неразмеченные данные, повреждённый импорт, восстановление
SQLite, демонстрацию и фильтры GUI. Тест интерфейса запускается без видимого окна.
Подробный результат — в `TEST_RESULTS.txt`.

Приложение не содержит системы ролей и шифрования. Ограничивайте доступ к папке
средствами ОС. Резервную копию `telecom.db` делайте после закрытия приложения.
